## What changed that Windows / Linux / Android get

Shared (commonMain / nativeDesktopMain / jvmAndroidMain):
- Device sync: a received file never overwrites a file with the same name (`name (1).ext`,
  `FreeFileName.kt`, received `.partN` / `.chunks` renamed); discovery listen retries every 5 s
  (`SyncDiscovery.kt`); UDP `SO_REUSEPORT` (native `KtorSyncNetwork.kt`, JVM/Android
  `JvmDeviceSyncPlatform.kt`).
- `DEVICE_SYNC_READY = true`: Settings > Devices and "Send to device" are visible in the native app.
- `displayChunks()`: paused downloads no longer show pieces as active (Compose + native details).
- Torrent remove with "also delete files" also deletes `<dest>/.<infohash>.parts`.
- Add download: torrent name box shows the torrent's name (`refreshSuggestedFileName`).
- JVM: no `InetAddress.getLocalHost()` on the UI thread (`DeviceHostName.jvm.kt`).
- Native desktop: `DesktopToolAssets` (per-OS media tool downloads), `BrowserLocator` (per-OS
  browser search), `SharedSecretKey` (null on Windows/Linux), `NativeApp.call("openUrl")`,
  accessibility roles in `desktopNative/ui/`.
- "Make FetchJet your main downloader" (`sharedLogic/.../core/setup/`): first-run dialog +
  Settings > General rows (default app for `.torrent` / `magnet:`, clipboard, start at login,
  extension offer). Windows: registers FetchJet under HKCU and opens the Default apps page; the
  WiX MSI now registers .torrent + magnet; Linux: `xdg-mime`; Android: share target + "Open with".
- CI: `desktop_engine` input (native default) in `build.yml`; Windows steps in
  `desktopNative/packaging/ci-windows.ps1`; Linux `build-linux.sh` adds `bin/FetchJet` link;
  native Linux in-app update (`PlatformUpdater.linux.kt`).
